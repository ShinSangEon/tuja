# 01. 설계

## 원칙

1. **지도는 마지막 10%.** 승부는 "신호를 얼마나 빨리, 깨끗하게 잡느냐"에서 난다.
2. **1차 소스 우선.** 공시(DART)와 지자체 공식 보도자료가 A급, 언론 보도는 B/C급. 등급이 낮으면 지도에는 뜨되 "미확인" 표시.
3. **지역은 한국 전체.** 시도/시군구/산업단지 3단계로 저장하고, 필터는 사용자가 고른다.
4. **"무엇이 필요하냐"까지 추출.** 회사·지역·금액뿐 아니라 압축기/드라이어/HMI 수요 가능성을 업종·공정·투자유형에서 추정해 점수화한다.
5. **사람이 마지막 판단.** AI는 후보를 만들고 등급을 매긴다. 영업 배정은 사람이 한다.

## 신호가 남는 순서 (단계 모델)

| stage | 뜻 | 대표 소스 | 설비 발주까지 |
|---|---|---|---|
| `disclosure` 공시 | 이사회 결의·공시 | DART 신규시설투자등 | 6~18개월 |
| `mou` 협약 | 지자체와 투자협약 | 지자체·산업부 보도자료 | 6~18개월 |
| `permit` 인허가 | 공장설립 승인, 건축허가, 산단 입주계약 | 팩토리온, 세움터, 산단공단 | 3~9개월 |
| `construction` 착공 | 기공식, 착공 보도 | 뉴스, 지자체 | 0~6개월 |
| `completed` 준공 | 준공식 | 뉴스 | 교체·증설 수요(장기) |

**영업 골든타임 = disclosure / mou 단계.** 압축공기 설비는 보통 건축 설계 단계에서 유틸리티 용량이 정해지고 착공 전후에 발주된다.

## 데이터 소스 (Phase 0 → 1)

### Phase 0 (지금 구현됨)
| 소스 | 방식 | 등급 | 비고 |
|---|---|---|---|
| DART 「신규시설투자등」 | OpenDART `list.json` → `document.xml` | A | 상장사만. 금액·기간·목적 표로 명시 |
| 네이버 뉴스 검색 API | 키워드 묶음 (`증설`, `신공장`, `공장 신설`, `설비투자`, `라인 증설`, `투자협약`) | C (2건 이상 교차 시 B) | 비상장·중견기업까지 커버. 노이즈 많음 → AI 분류로 걸러냄 |
| 보도자료 (sources.yaml) | RSS 또는 HTML 목록 크롤링 | A | 산업부, 17개 시도, 주요 시군. **URL·선택자는 등록 필요** |

### Phase 1 (소스 추가)
| 소스 | 방식 | 등급 | 메모 |
|---|---|---|---|

## 파이프라인

```
수집(raw_documents) ─▶ out/pending.md ─▶ Claude 세션에서 추출 ─▶ out/extracted.json ─▶ 검증·병합(signals) ─▶ 지오코딩 ─▶ 대시보드
       │                                     │ (API 미사용, 하루 1회 수동)                      │
       └─ 원문 그대로 보관                    └─ 문서 1건당 JSON 1건 (extractions 에 저장)         └─ 같은 프로젝트는 signal 1건,
          (재추출 가능)                                                                            signal_sources 로 출처 N건 연결
```

- raw_documents: 소스별 원문. 같은 URL은 한 번만 (해시).
- extractions: AI가 뽑은 구조화 결과. 실패·저신뢰도 포함 전부 저장 (품질 분석용).
- signals: 최종 "투자 건". 등급(A/B/C), 규모(S/M/L), 단계, 좌표, 관련도 점수.
- signal_sources: signal ↔ raw_documents N:M.

## 로드맵

- **Phase 0 (지금 ~ 2주)**: DART + 네이버뉴스 + 보도자료 3~5곳. 지도에 핀. 대표이사 시연. 분류 기준 합의.
- **Phase 1 (1~2개월)**: 소스 10곳+, collect 스케줄(Actions), 산단 마스터, 건축허가 연동, 필터·검색 고도화, 주간 다이제스트 메일.
- **Phase 2**: 영업 액션 레이어 — 담당자 배정, 접촉 상태, "누구 통해 연결 가능" 메모, 알림(슬랙/카톡). 핀 하나 = 다음 액션 하나.
- **Phase 3 (해외)**: 지도 레이어 추상화(`MapProvider`) 후 Google/Mapbox 교체. 소스는 나라별 신규 구축 (중국 环评公示·招商, 일본 適時開示, 베트남 IZ 투자허가).

## 설계상 의도적으로 안 한 것

- Claude API 자동 추출: 하루 1회 세션에서 수동으로 충분하고 비용 0. 물량이 늘면 `extract.py INSTRUCTIONS` 를 그대로 시스템 프롬프트로 써서 전환.
- 실시간 스트리밍: 하루 1회 배치로 충분. 투자 공시는 분 단위로 안 바뀐다.
- 벡터 검색/RAG: 지금 규모(월 수백 건)에선 PostgreSQL 전문검색으로 충분.
- 마이크로서비스: Python 스크립트 1개 + Next.js 1개. 사람이 1명이면 이게 맞다.
